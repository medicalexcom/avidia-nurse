## Chunking architecture (ADR-0011)

Structural semantic chunking from M4 sections — never blind windows:

- PPTX: one core chunk per slide (title + body); tables and speaker notes
  are separate chunks (tables carry the slide title as context).
- PDF: one chunk per page; oversized pages split at line boundaries.
- DOCX/TXT: heading-scoped groups up to the budget; tables stand alone with
  the nearest heading prefixed.

Sizes: budget ~480 tokens (chars/4 heuristic, 1920 chars). Overlap: only at
structural split points — the previous part's final line (≤240 chars) is
carried into the next part (`part: N` in the locator); no blanket sliding
window; hard splits carry none. Tables: split at row boundaries with the
header row repeated in every part, so rows keep their column meaning.
Deterministic: same sections in, same chunks out.

## Embeddings (ADR-0012)

- Provider/model: OpenAI `text-embedding-3-small`, dimension **1536**,
  `EMBEDDING_VERSION = 'v1'` — stored per chunk as
  `embedding_provider/model/version`.
- Plain `fetch`, batches of 100, bounded retry (3 attempts, backoff) on
  429/5xx/network; count and dimension validated on every response.
- `HashingEmbeddingProvider` (FNV-1a bag-of-words, L2-normalized, same
  1536-dim space) powers tests, the eval set, and keyless local dev
  (`EMBEDDING_PROVIDER=hashing`). Never for production.
- Batch/cost discipline (spec V): one claim per document (CAS prevents
  duplicate embedding), provider-side batching, and the worker logs chunk
  count + summed token estimate per document for approximate cost tracking.

## pgvector setup and index (ADR-0013)

`create extension vector with schema extensions`; `vector(1536)` column;
`hnsw (embedding vector_cosine_ops)` at defaults (m=16, ef_construction=64)
— no training step, good recall at MVP scale. Lexical side: stored generated
`content_tsv` tsvector column with a GIN index.

## Retrieval algorithm and scoping

`search_course_chunks(course, query, embedding, top_k, min_similarity,
document_id?)`:

1. Ownership check inside the function: raises unless the authenticated
   caller owns the course (service role, with no user context, is allowed
   for the internal CLI). Anonymous callers have no EXECUTE grant.
2. Vector leg: cosine ordering over a pool of 4×top_k (min 20).
3. Lexical leg: `websearch_to_tsquery('english')` over `content_tsv`.
4. Fusion: reciprocal-rank fusion, `Σ 1/(60 + rank)`; `min_similarity`
   filters only the vector leg (exact-term lexical hits always survive).
5. Returns chunk id, document id + filename, ordinal, content, locator,
   similarity, lexical rank, fused score. **Never the embedding.**

Hybrid decision (spec L): implemented — nursing vocabulary is dense with
exact tokens (FEV1, PaCO2, DKA, Kussmaul, INR) that pure vector search
fuzzes over; the lexical leg guarantees literal matches while the vector leg
covers paraphrase. RRF avoids score-normalization fragility.

Product access goes through `CourseKnowledgeRetriever.search()` (embeds the
query, delegates to the RPC seam); no screen queries pgvector directly.

## Grounding and citation contracts (spec N/R)

`buildGroundingContext(query, results)` returns `{query, sources[],
textBlocks[], insufficient}`. Every block is labeled `[S1] (Adult Health
Module 3 — slide 17)\n<text>`; each source carries chunk id, document id and
title, the raw locator, a human citation, and the score. `insufficient` is
set when retrieval returned nothing — the future M10 answering call MUST
label such content platform-derived, never course-attributed (Playbook §17).
Citation contract: document title + id, source type, page/slide/section
(+ table/notes/part annotations), chunk id.

## Indexing lifecycle and re-indexing (spec I/J/W)

`documents.index_status`: `pending → indexing → indexed | failed`, with
`index_attempts`, `index_detail` (internal), `indexed_at`. Extraction's
`markReady` resets it to `pending`, so re-extraction always rebuilds chunks
(no stale chunks). Chunk replacement is atomic (delete + insert in one RPC
transaction). Stale `indexing` rows are swept back to `pending` (internal,
retryable — students are never asked to act on an indexing failure).
Deleting a document or course cascades to its chunks; retrieval is clean
immediately.

## Privacy (spec U)

Only chunk/query text goes to the embedding provider — no identities, no
filenames. Raw vectors are server-side only: excluded from client column
grants and absent from every RPC result. Full data-flow note in ADR-0012.

## Retrieval-quality findings (spec S)

Eval set: 6 synthetic nursing chunks (heart failure, furosemide,
hyperkalemia, PE, COPD, DKA) across 3 documents; 6 queries with expected
hits, run through the hashing provider and an in-memory replica of the
hybrid RRF backend. Results: **hit@1 = 100%, hit@3 = 100%**; exact-term
queries (FEV1, PaCO2, Kussmaul, furosemide) resolve through the lexical
leg; uncovered queries return empty under a threshold and are marked
`insufficient`. Caveat: this measures the pipeline with a lexical baseline
embedding; production semantic quality (paraphrase recall) requires the
OpenAI provider and live data — first thing to re-measure after deploy.

## Known limitations

- Token budget is a chars/4 heuristic, not a tokenizer.
- The eval set is small and lexical-leaning; add paraphrase-heavy queries
  once the OpenAI provider is live.
- `concept_id` is a placeholder; ontology/concept map deferred.
- HNSW/RRF parameters are defaults; tune only if the eval says so.
- Manual verification against a live Supabase project is pending (see
  README setup; migration 0005 must be applied and worker env configured).
