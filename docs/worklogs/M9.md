# M9 — Daily adaptive study experience

Date: 2026-08-13. Builds on M8 (`0fa1d0d`).

Scope note: M9 turns the M8 engine into the product students actually touch
every day — a Today home screen whose central action is START TODAY, and a
duration-based adaptive session that plans, adapts, resumes, and summarizes
honestly. The screen layer added here contains NO prioritization, mastery, or
scheduling logic of its own (spec C): every priority, due review, and
recommendation is the pure `@avidia/mastery` ranking over the student's own
rows, and every mastery number comes back from the server's `submit` RPC.
There is deliberately no AI chat box on home (spec AE), no gamification, no
push notifications, and no deep analytics (spec AH); streaks are deferred to
M10 by design (spec AA).

## What shipped

### Today / Home screen (spec A/B/P/R/AC/AD/AE)

- `app/(app)/home.tsx` now renders `TodayScreen`
  (`src/features/today/screens/TodayScreen.tsx`): active course, next-exam
  countdown (same timezone-correct domain utility as everywhere else), a
  due-for-review row consuming M8's stored `next_review_at` (spec R — no
  second scheduler exists), the top three priorities with their mastery-state
  labels and deterministic reason labels (spec H), recent sessions (spec AC),
  and the primary CTA: four duration chips (5/10/20/45 min, spec B) that
  launch `/course/:id/practice?mode=adaptive&minutes=N`. Counts and labels
  only — no percentages, scores, or predictions (spec A/M).
- Course defaulting is pure and tested (`todayApi.pickDefaultCourseId`,
  spec P): the ACTIVE course with the soonest future exam wins (exam
  pressure is the strongest "what is today about" signal), else the newest
  active course, else the newest course of any status. A chip selector
  appears only when the student has multiple courses.
- Empty states guide action (spec AD): no courses → "Create your first
  course"; a course with no validated questions → "Upload course material".
  An in-progress session surfaces a "Continue your session" card (spec O).

### Duration-based session planning (spec B/D/X)

- `src/features/today/plan.ts` is a pure, fully unit-tested module:
  `questionCountForDuration` maps minutes → question count at ~75 s per
  question (5→4, 10→8, 20→16, 45→36), clamped to 3–50 and capped by the
  validated pool — a small bank shrinks the session honestly instead of
  blocking or calling AI (spec X; `question_supply_low` remains an M8 reason
  code, never a generation trigger). `estimateRemainingMinutes` powers the
  gentle "~N min left" line (spec I) — informational, never a countdown that
  rewards rushing.

### The daily session flow (spec C/E/F/G/H/I/J/K/L/N/Q/S/T/AB)

- `PracticeScreen` gained an M9 adaptive mode while preserving the M7
  practice mode untouched (spec S — basic practice remains, and a
  practice-mode test pins that it still never reads mastery or exams).
- Session start: the pure engine picks and orders questions from the
  persisted bank (`buildAdaptiveQuestionOrder`, seeded by session id), the
  session row stores `requested_duration_minutes`, and the chosen order is
  bulk-written to `study_session_plan` as the resume baseline (ADR-0025).
- One question at a time (spec E) through the existing M7 flow — confidence
  is one optional tap (spec F), scoring stays server-side, answers lock.
- Rationale display is concise-first with "Explain more" (spec G); "View
  source" fetches the provenance chain (`question_sources` → document
  filename + slide/page locator) on demand and shows it in student terms —
  never chunk ids or vector scores, which the grants don't even allow the
  client to read (spec T).
- "Why am I studying this" (spec H) renders the concept name plus the top
  M8 reason-code labels — deterministic strings, not AI text. When the
  misconception factor is active the panel adds the respectful line "Let's
  revisit this concept from a different angle." — copy is tested to never
  contain "dangerous", "misconception", "wrong", "fail", or "bad" (spec L).
- Mid-session adaptation (spec J/K): each `submit_question_attempt` echoes
  the full post-update mastery aggregate (`v_mastery_json`, migration 0008);
  the client applies it verbatim (spec C — no client arithmetic), re-ranks,
  and deterministically reorders only the REMAINING questions (seed
  `sessionId:answeredCount`). Answered ids are subtracted first, so the
  just-answered question cannot immediately repeat (spec K).
- Exam mode is not a mode (spec Q): exam proximity flows through M8's
  urgency factor into the very same ranking.
- Pause/exit/skip (spec AB): "Skip for now" marks `skipped_at` on the plan
  row — tracked explicitly, never recorded correct/incorrect, never touching
  mastery, and never counted against the student in the summary. "End
  session" closes honestly (completed if anything was answered, else
  abandoned).

### Resume (spec O, ADR-0025)

- `findResumableSession` surfaces the newest in-progress adaptive session on
  both Today and the session setup screen; the student may continue it or
  explicitly start fresh (the old one is closed as abandoned — never
  silently discarded). Resume = stored plan − answered (from
  `question_attempts`, the single attempt truth, spec Y) − skips − retired
  questions; answered work is never re-asked and mastery is never
  double-updated. A plan found fully answered auto-closes as completed.

### Honest completion summary (spec M/D)

- The summary reports what is knowable: activities completed and correct,
  skips ("skips never count against you"), concepts reviewed, concepts with
  net-positive mastery movement ("Moving forward"), due reviews completed,
  what still needs attention, and a recommended next focus with its state
  label. No fake precision — no percentages-mastered, no predicted scores.
  Ending early still produces this summary from whatever was done (spec D).

### Quick sessions (spec N)

- 5- and 10-minute launches use the SAME adaptive pipeline — the only
  difference is the question count (and a `quick_session_started` analytics
  event). There is no disconnected "quick mode".

### Session events & history (spec Y/AC/Z)

- No new attempt state was invented: activity counts come from
  `question_attempts(count)`; skips live only as `skipped_at`. Sessions
  gained exactly one column (`requested_duration_minutes`).
- `todayApi.listRecentSessions` renders the last five sessions (date +
  activity count) — the M12-ready history foundation, not analytics.
- `src/lib/analytics.ts` (spec Z): a typed in-process event buffer
  (`daily_session_started/completed/abandoned`, `quick_session_started`,
  `source_viewed`, `explain_more_used`) with NO network transport in v1.
  Privacy is enforced by construction — the payload types physically cannot
  carry course text, questions, answers, or mastery numbers.

### Migration `0009_daily_study_sessions.sql` (spec O/AB/AF)

- `study_sessions.requested_duration_minutes` (nullable, check 1–120, insert
  grant added).
- `study_session_plan`: `(session_id, position 1–50, question_id,
skipped_at)` with RLS forced — select/insert/update-own only (insert only
  into one's own in-progress session with a same-course question),
  `skipped_at` the sole updatable column, no client delete, cascade from the
  session. Authz checks 45–48 pin all of it.

### Failure tolerance (spec W/X)

- Plan persistence, resume detection, and skip marking are each best-effort:
  any of them failing leaves a fully working in-memory session (only
  resume-after-restart degrades, for that one session). Study never requires
  an AI provider — everything runs from the validated persisted bank.

## Manual validation walkthrough (spec AG)

1. Sign in and open the app — you land on Today, not a course list.
2. With no courses: Today shows the welcome and "Create your first course";
   pressing it goes to course creation.
3. Create a course with an exam date next week; upload a slide deck; wait
   for processing and question validation.
4. Before questions exist: Today shows "Add material to unlock daily study"
   with an upload button — no dead ends.
5. Once questions exist: Today shows the exam countdown, START TODAY with
   5/10/20/45 min chips, and Today's priorities with plain-language reasons.
6. Press "20 min" — a session starts immediately with "Question 1 of N"
   (N ≈ 16, smaller if your bank is small) and "~N min left".
7. Each question shows "Why this:" with the concept and reasons like
   "Not assessed yet" or "Exam coming up" — no AI-generated explanation.
8. Answer one confidently wrong twice across sessions — the panel adds
   "Let's revisit this concept from a different angle." and never any
   harsh wording.
9. Submit an answer — the rationale's first sentence appears with "Explain
   more"; pressing it reveals the full rationale.
10. Press "View source" — you see the document filename and slide/page,
    never chunk ids or scores.
11. Press "Skip for now" on a question — it advances without judging you;
    the summary later shows "Skipped: 1 (skips never count against you)".
12. Kill the app (or refresh the browser tab) mid-session.
13. Reopen — Today shows "You have a session in progress"; press Continue:
    you're on the next unanswered question, and previously answered ones do
    not reappear.
14. In the same state, choose "Start a new session instead" on the setup
    screen — the old session is closed, a fresh one starts.
15. Finish a session — the summary lists activities, correct count,
    concepts reviewed, "Moving forward", due reviews completed, and a
    recommended next focus. No percentages anywhere.
16. Press "Back to Today" — the session now appears under Recent sessions.
17. Once `next_review_at` passes for a concept (or move the clock), Today
    shows "Due for review: N concepts"; "Review now" starts a 10-min
    session that includes it.
18. Press "5 min" — same experience, just shorter (a quick session).
19. "Free practice" in the footer still runs plain M7 practice with
    question-count choices — untouched.
20. Sign in as a second user — none of the first user's sessions, plans, or
    history are visible anywhere (RLS; pinned by authz checks 45–48).

## Known limitations (honest, not defects)

- After a resume, the summary attributes mastery deltas only to answers made
  since the resume; pre-restart deltas are not re-fetched in v1 (the
  aggregates themselves are always server-truth). ADR-0025 documents this.
- Question numbering after a resume restarts at "Question 1 of remaining" —
  honest about what's left rather than pretending continuity of position.
- Analytics events have no transport yet (spec Z is satisfied in-process);
  wiring a privacy-preserving sink is future work.
- `requested_duration_minutes` is informational; sessions end by plan
  completion or the student's choice, never a hard timer.

## Handoff to M10 (NOT implemented, spec AH/AA)

M10 can consume: `study_sessions` (+ duration) and `study_session_plan` for
streak/consistency features (spec AA explicitly deferred streaks to M10);
the analytics event names for lightweight engagement metrics; the
recent-sessions foundation for richer history. Deliberately absent, for
M10+ to decide: notifications/reminders, streaks and any motivational
mechanics, timed/exam-simulation modes, deep progress analytics (M12), and
an analytics transport.
