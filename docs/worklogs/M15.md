# M15 — Final Integration, Beta Hardening, Release Readiness, and v1 Acceptance

Date: 2026-08-14. Builds on M14 (`e03a17d`). **Final milestone of the
Avidia Nurse v1 build sequence — there is no M16.**

Scope note: M15 added no product features. It audited, verified,
hardened, fixed, documented, and packaged the complete M0–M14 system,
and produced an honest v1 acceptance verdict. The build environment has
no live Supabase project, no real devices, and no store accounts —
every check below is therefore labeled with what was actually executed
versus reviewed versus not testable. Nothing is called "verified" that
was not run.

## What M15 did

### Repository audit (spec A)

Full-tree review (three independent audit passes: code quality,
security, platform readiness). Results: zero TODO/FIXME/HACK comments;
all console logging is intentional structured logging (worker, edge
functions, `__DEV__` analytics echo); no development bypasses, no
hardcoded IDs in production paths, no dead code or duplicate business
logic found; the only stub is the documented `notConfiguredPurchases`
store-billing adapter; no unused dependencies detected. The scripted
question provider is env-gated (`QUESTION_PROVIDER=scripted`) and never
a default. One earlier audit claim — "no student content-report path" —
was disproven on verification: "Report a problem" exists on every
practice question and writes to `question_feedback` (0007, RLS-scoped,
stored-never-auto-applied).

### Fixes shipped (all small, none architectural)

- `apps/app/app.json`: added `ios.buildNumber: "1"`,
  `android.versionCode: 1`, `ITSAppUsesNonExemptEncryption: false`, and
  the `expo-notifications` plugin (the app already used the module
  without declaring the config plugin) — closing the store-build
  blockers found in spec AL/AM review.
- `apps/app/eas.json` (new): development / preview / production build
  profiles, internal distribution for preview, `autoIncrement` for
  production build numbers, `appVersionSource: remote`.
- `ResponsiveShell`: explicit `accessibilityLabel` on the five nav
  destinations (previously label came only from child text) and
  `minHeight: 48` on bottom-tab items to guarantee ≥44pt targets.
- Auth layout: `KeyboardAvoidingView` + scrollable centered card so the
  email/password fields stay visible above the soft keyboard on small
  phones (spec C).

Deliberately NOT changed (spec: no redesigns, no risky refactors):
mastery constants, planner logic, simulation engine, dark mode,
per-screen error boundaries, offline caching, password reset (each
recorded in `KNOWN_LIMITATIONS.md`).

### Documentation shipped (spec AX)

`docs/BETA_READINESS.md`, `docs/RELEASE_CHECKLIST.md`,
`docs/KNOWN_LIMITATIONS.md`, `docs/ENVIRONMENTS.md`,
`docs/SECURITY_OVERVIEW.md`, `docs/OPERATIONS_RUNBOOK.md`, this worklog,
and the README v1 summary.

### Security audits (spec G–K)

- Service role: referenced only in the worker, the authz harness, CI
  secret wiring, and docs; zero references under `apps/app`; every
  `EXPO_PUBLIC_*` variable inventoried and non-secret.
- Secret scan: pattern sweeps of the tree plus `git log -S` history
  probes for Stripe/webhook/JWT/PAT/AWS/postgres-credential patterns —
  nothing found; gitleaks runs in CI on full history.
- Dependencies: `pnpm audit --audit-level high` exits 0; 3 ignored
  advisories (rationale in M14 worklog) re-checked and still correct;
  1 remaining moderate advisory, non-blocking.
- Auth boundaries: pure `decideRoute` guard, session restoration, no
  flash of protected content. Password reset absent → documented P2.
- Deep links: strict allowlist (`/planner`, `/home`, `/study`; unknown →
  `/home`); deep links cannot bypass the auth gate.
- RLS review: all user-data tables across 0001–0015 have RLS enabled and
  forced; the only broader-than-owner reads are the two documented,
  intentional cases (active `simulation_cases`, `feature_flags`); all
  SECURITY DEFINER functions validate caller scope or are trigger/
  service-role-only with explicit revokes.

### Platform readiness (spec C/D/E/F, AK/AL/AM)

Static review (no devices available): SafeArea via provider + shell
insets throughout; all major screens scroll; touch targets ≥44pt
(after the tab fix); no modals to audit (inline confirm pattern);
responsive shell switches bottom-tabs ↔ sidebar at 768px; Analytics
(≥900px two-column) and Simulation (≥900px three-column) have real
desktop layouts; all screens use a centered max-width container — the
web build is a usable desktop app, not a stretched phone. Business
rules live exclusively in `packages/*`; the only `Platform.OS` branches
are infrastructure/UI (storage adapter, notifications no-op on web,
share-vs-download for export) — no business drift is possible between
platforms. Web export (`expo export --platform web`, SPA output) builds
clean. iOS/Android build config is now complete to the limit of what
exists without developer accounts.

### Resilience posture (spec S/Y/Z, AW)

Verified in code and tests: AI-provider failure marks documents
`failed` with student-safe copy and retry (worker tests cover rate
limits, corrupt bytes, stale-processing recovery); no raw provider
errors reach students anywhere (each major screen has a friendly error
state + retry; billing maps errors to plain messages); everything
already persisted — practice, mastery, reviews, adaptive study,
analytics, planner, canonical simulations — is deterministic and works
with AI down; only NEW content creation (document processing, question
generation) requires AI. Entitlement fetch failure: 72h bounded cache,
UI fails open, database triggers still enforce.

### Feature flags (spec AO)

Exactly one runtime flag exists: `subscriptions` (database row, default
FALSE). No obsolete flags to remove; the M12 nav placeholders were
already flipped live. Production default: keep FALSE until the founder
launches billing (one-row UPDATE, documented in the runbook).
