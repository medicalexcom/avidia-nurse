# M7 — Nursing question and assessment engine

Date: 2026-08-13. Builds on M6 (`b6c89bc`).

Scope note: this milestone ships source-grounded question generation and a
deterministic practice loop with server-side scoring. It is explicitly NOT
adaptive: no mastery tracking, no weakness modeling, no spaced repetition,
no difficulty adjustment mid-session (non-goals AL). Those consume this
data in M8+.

## What shipped

- **Migration `0007_questions_and_assessment.sql`** — `questions` (typed,
  lifecycle `generated/active/flagged/rejected/retired`, content-hash dedup
  unique per course, numeric answers as CHECK-constrained data),
  `question_options` (deterministic ordinals; `is_correct`/
  `correct_position`/option rationale excluded from client grants),
  `question_sources` (question↔chunk provenance verified against the
  document), `study_sessions`, `question_attempts` (no client write path at
  all; `unique(session_id, question_id)` immutability), `question_feedback`
  (stored, never auto-applied), the FOURTH document lifecycle
  `question_status` (pending → generating → ready | failed) with fingerprint
  column, the worker-only `apply_question_generation` RPC (transactional,
  idempotent, dedup-aware, retires evidence-less questions), the
  SECURITY DEFINER `submit_question_attempt` RPC (ownership check → shape
  check → deterministic scoring → insert → only then reveal), and an
  `AFTER DELETE` trigger on documents retiring course-grounded questions
  that lost all evidence. Answer-revealing columns are not selectable by
  ANY client — enforced by column grants, not application code.
- **`@avidia/assessment` package** — strict generation schema + structural
  validator (spec J), the clinical validation pipeline (reject vs. flag,
  high-risk strictness for insulin/anticoagulants/dosing/emergencies,
  answer-leakage and distractor-quality checks, spec K/L/N), the
  provider-independent generation gateway (`gpt-4o-mini` strict
  JSON-schema mode + scripted offline provider, one repair round, versioned
  prompt p1/generation v1), deterministic scoring mirrors of the SQL,
  content hashing + dedup, the generation fingerprint cost gate, concept
  picking (top-8 by transparent M6 emphasis) and the seeded deterministic
  session mixer (`mix.ts` is dependency-free so the app can deep-import it
  without pulling node `crypto` into the web bundle), plus synthetic
  nursing eval fixtures (hyperkalemia, DKA, PE, COPD, HF, furosemide — no
  NCLEX content, spec AI).
- **Worker questions stage** — knowledge-ready documents flow through
  CAS claim → fingerprint gate ("questions unchanged (fingerprint match,
  no AI call)") → provider → validate → RPC apply → ready, with 15-minute
  stale-claim recovery and failure isolation: a failed generation never
  touches reading/retrieval/knowledge, and re-extraction of a document
  resets its question lifecycle so questions track current content.
- **Domain** — question/type/difficulty/cognitive-level/priority-framework/
  confidence/feedback taxonomies with student-facing labels and guards
  (71 domain tests).
- **App** — Practice: session setup (5/10/20 capped by pool), per-type
  interactions (SBA select, SATA multi-select, ordered tap-to-sequence
  with reset, numeric input with comma tolerance), optional confidence
  chips, submit → server-scored reveal with per-option verdicts and
  teaching rationales, locked answers, plain results ("You answered N of M
  correctly" — no mastery/weak labels, spec X), post-answer flagging with
  the five reasons and the honest note that a report never changes the
  answer by itself, and abandoned-vs-completed close semantics.
- **Authz harness** — M7 checks 34–40: generation RPC denial; direct-write
  denial on questions/options/sources/attempts; answer-column selection
  denial; flagged invisibility; cross-user/anon guessed-id denial on every
  table; session ownership + column grants; RPC scoring incl. numeric
  tolerance; immutable re-answer refusal; feedback scoping and
  non-application; document-delete retirement; course-delete cascade over
  the whole assessment layer.

## Key decisions (ADRs 0018–0021)

- **Schema-enforced no-leakage** (ADR-0018) — the answer key is a set of
  columns clients cannot SELECT; the only reveal is the scoring RPC's
  return value after the attempt row exists.
- **Background generation, never in the study path** (ADR-0019) — students
  can always practice from persisted questions; no screen calls a
  provider; unchanged material never re-bills (fingerprint gate).
- **Server-side deterministic scoring** (ADR-0020) — one write path
  (`submit_question_attempt`), set/sequence/tolerance rules mirrored and
  contract-tested in TypeScript, immutability by unique constraint.
- **Reject vs. flag** (ADR-0021) — malformed/misleading items never
  persist; quality/safety smells persist as `flagged` (student-invisible)
  with named flags; high-alert topics get stricter numeric/rationale
  rules; student feedback is stored but never auto-applied.

## Quality evaluation (spec AI/AJ)

The scripted provider + eval fixtures make the full pipeline repeatable
offline: generation → schema gate → clinical validation → RPC payload →
worker persistence flow → session mixing → scoring, including doctored
batches (two-correct SBA, leaky stem, giveaway distractor) proving the
gates catch them. 293 → 380 tests, no API key needed.

### Manual validation steps (spec AK — run once Supabase project exists)

1. Apply migration 0007; confirm the six assessment tables exist with RLS
   forced and the restricted column grants (`\dp questions` shows no
   rationale/expected_value in the authenticated SELECT grant).
2. Upload a document with clear clinical content (e.g. an electrolytes
   lecture); watch `question_status` go pending → generating → ready after
   `knowledge_status` is ready.
3. Inspect generated rows: every question is `active` or `flagged`, has
   3–6 options (or none for numeric), a content hash, provider/model/
   prompt/generation versions, and `question_sources` rows pointing at
   real chunks of that document.
4. As the student, open Course → Practice; confirm only ACTIVE questions
   are offered and the pool size matches.
5. Via the API, SELECT `rationale`/`expected_value` on `questions` and
   `is_correct`/`correct_position` on `question_options` with the owner's
   JWT; confirm database errors, not data.
6. Start a 5-question session; confirm the same session id always yields
   the same question order (deterministic seed), and a new session yields
   a different mix.
7. Answer an SBA correctly; confirm the reveal shows per-option verdicts
   and rationales only AFTER submission, and the attempt row's
   `is_correct` was computed server-side.
8. Try to re-answer the same question in the same session (replay the RPC
   call); confirm "question already answered in this session".
9. Answer a numeric question within tolerance (e.g. expected 2 ± 0.1 with
   2.05) and outside it; confirm correct/incorrect accordingly and that
   the unit + rounding note appear in the reveal.
10. Submit a response citing an option id from a different question;
    confirm the RPC rejects it and no attempt is recorded.
11. Attempt direct INSERT/UPDATE/DELETE on `question_attempts` and
    UPDATE on recorded attempts; all denied.
12. As user B, call `submit_question_attempt` with A's session id and
    read A's questions/options/sessions/attempts by guessed ids; all
    empty or errors, indistinguishable from nonexistent ids.
13. Flag a question as "The answer is wrong"; confirm the feedback row
    exists, and the question's status, options and answer key are
    byte-identical afterwards.
14. Confirm a `flagged` question (force one via a high-risk fixture with a
    wide tolerance) never appears in any practice session.
15. Re-run the worker with no content changes; logs must show the
    fingerprint skip and the provider must receive zero requests.
16. Replace the document's file; confirm `question_status` returns to
    pending, regeneration runs, unchanged items dedup (skipped, not
    duplicated) and provenance is refreshed.
17. Delete a document whose questions have no other evidence; confirm
    those course-grounded questions become `retired` and disappear from
    practice, while multi-source questions survive.
18. Delete the course; confirm zero rows remain in all six assessment
    tables for it.
19. Kill the worker mid-generation; confirm the 15-minute stale sweep
    returns the document to pending and the retry produces no duplicate
    questions (idempotent RPC + content hash).
20. Set an invalid `OPENAI_API_KEY`; confirm generation fails fast with
    stored detail, the document's reading/retrieval/concepts still work,
    and existing questions remain fully practicable (spec AE — studying
    needs no live LLM).

## Known limitations

- Flagged questions have no review UI yet; they accumulate with named
  flags until a curation milestone.
- The scripted provider exercises the pipeline, not model quality;
  live-model quality against the fixtures needs an API key and is a
  manual run.
- Offline practice renders cached questions but cannot score until
  connectivity returns (the answer key never ships to the device —
  deliberate, ADR-0020).
- SATA scoring is all-or-nothing; partial credit is a product decision
  deferred with M8.

## Handoff to M8 (data contract, spec AM)

M8 (mastery/analytics) can consume: immutable `question_attempts`
(response, server-scored `is_correct`, `response_time_ms`, optional
`confidence`, timestamps), `study_sessions` lifecycles, question metadata
(type, difficulty, cognitive level, concept link, priority frameworks,
source type) and question↔chunk provenance. Every attempt was scored by
the database against server-held answers and can be trusted as ground
truth. Not started here per instruction.
