# M10 — Advanced study modes, clinical drills, and learning-centered gamification

Date: 2026-08-13. Builds on M9 (`c96d1cf`).

Scope note: M10 adds the blueprint's in-scope study modes — Rapid Response,
Find the Danger, Who First?, Medication Lab, and Boss Battle — plus the one
gamification mechanic the product documents approve: streaks. The
instruction's "Priority Challenge" is the blueprint's "Who First?"
(prioritization drills), and the instruction's fast-retrieval "Rapid
Response" is distinct from the blueprint's Phase-2 deterioration-management
mode of the same name; per the instruction, the authoritative documents'
scope was followed. Core principle throughout: GAMIFICATION SERVES
LEARNING — every mode is the same validated bank, the same server scoring,
and the same single mastery model wearing a different practice structure.

## What shipped

### The shared activity contract (spec A/O/P)

No new contract was invented, deliberately: every mode presents rows from
`questions`, inside a `study_sessions` row, scored by
`submit_question_attempt` — the pipeline M7 built and M8 wired into
mastery. One question → one scored attempt → one server-computed mastery
update IS the normalized evidence contract, so M8 receives identical
evidence from every mode, there is no separate game mastery (spec O), and
evidence weighting stays centralized where M8 documented it (spec P).
Response speed already has no mastery effect (`RESPONSE_TIME_FACTOR` is
neutral in the M8 engine) — exactly the bounded behavior spec D requires:
Rapid Response can feel quick without "fast answer = good nurse" ever being
implied, and slower learners are never penalized (spec AF).

### The mode registry (spec B, ADR-0026)

`src/features/modes/registry.ts` is a pure, fully unit-tested catalog. A
mode is data: an `includesQuestion` predicate over STORED question facts
(type, difficulty, cognitive level, priority frameworks, concept type —
never text-matching, never AI) plus a deterministic seeded `buildOrder`.
Screens iterate the registry; adding a mode is one entry, zero screen
conditionals. Eligibility is explicit (spec S/T): each mode declares a
minimum question count and a guiding locked message.

- **Rapid Response** (spec C/D): easy/moderate recall and understanding
  questions — fast retrieval of foundations. The tagline says it outright:
  "Accuracy is what counts — take the time you need; speed never changes
  your mastery."
- **Find the Danger** (spec E): single/multiple-response questions on
  safety, complication, sign/symptom, risk-factor, or assessment concepts
  (or carrying the safety framework) — recognizing the cue that matters.
- **Who First?** (spec F): questions with prioritization cognitive level or
  priority frameworks — defensible nursing prioritization, graded by the
  server against the question's validated key, never by mechanical
  ABC-order assumptions in client code.
- **Medication Lab** (spec G/H): questions on medication/calculation
  concepts plus numeric calculations — arithmetic is checked by the M7
  tolerance-aware calculation engine, and every scenario is course-grounded
  (spec N); nothing invents dosages outside uploaded materials.
- **Boss Battle** (spec I/J/K): the whole validated bank in rounds —
  Foundation → Application → Prioritization → Integrated — each round
  concept-balanced with its own derived seed. Rounds a small bank cannot
  fill simply do not appear; results never predict exam outcomes.

### Mode sessions in the existing flow (spec C/Q/U/AI/AL)

`PracticeScreen` gained a mode launch alongside practice and adaptive:
the eligible sub-pool is filtered by the registry, the session row is
honestly labeled with the mode id (migration 0010 extends the
`session_type` check constraint — the ONLY schema change of M10), and the
order is FIXED and seeded for the whole session: drills have a shape, so
mid-session re-ranking remains an adaptive-mode behavior. Mode sessions
show concise-first rationales, "View source" provenance, and the plain
honest results screen — counts, no percentages, no fake precision (spec
U). Everything runs from the persisted bank with no AI provider (spec AI).
Scoring semantics are untouched M7 server truth; no client-side partial
credit was invented (spec Q — the client displays exactly what the server
granted). M7 practice and M9 adaptive modes are provably untouched (their
suites run unchanged).

### The Study Modes screen (spec S/T/AD/AE)

`app/(app)/course/[id]/modes.tsx` → `ModesScreen`: all five modes always
visible, eligible ones launch with an honest question count, locked ones
explain exactly what unlocks them ("Medication Lab unlocks when your course
materials cover medications…") — no dead ends, no hidden features. Today
links to it via a "Study modes" footer entry; START TODAY remains the
primary daily action (spec R — modes are never forced into daily sessions).

### Streaks — the approved gamification (spec V/W/X/Y/Z/AA, ADR-0027)

The product documents approve exactly one motivational mechanic: streaks.
XP, levels, points, badges, and achievements appear in none of them, so
M10 does not build them (and thereby has no XP-forgery surface at all).
`src/features/modes/streak.ts` derives the streak PURELY from the
student's own server-written `question_attempts` timestamps — zero new
state, timezone-correct via the domain's `calendarDateInZone`, recomputable
at any time. Non-punitive by construction: a run ending yesterday still
counts before today's study; copy is quiet ("Study streak: 3 days — today
counts."), never threatens loss, and a zero streak shows nothing. Today
renders it as one muted line — restrained feedback, no animations, no
sound (spec AB/AC).

### Analytics (spec AJ)

One event was added to the typed in-process buffer: `mode_session_started`
with the mode id — a name and an enum, physically unable to carry course
content or mastery numbers. No transport, unchanged from M9.

## Migration `0010_study_modes.sql`

Extends `study_sessions.session_type` with the five mode ids. No new
tables, no new columns, no RLS changes — modes reuse the owner-scoped
session/plan/attempt machinery end to end (spec AK/AL). Authz check 49
pins that all five values are accepted for one's own course and that an
invented session_type is rejected.

## Manual validation walkthrough (spec AP)

1. Sign in — Today now shows a "Study modes" entry in the footer.
2. Press it: all five modes are listed with taglines.
3. With a fresh course (no questions): every mode is locked, each with a
   message that says what to do next — no dead ends.
4. Upload material; once questions are validated, revisit: modes with
   enough eligible questions show "N questions available" and a start
   button; the rest stay locked with their guidance.
5. If your material has no medications, Medication Lab stays locked with
   "upload pharmacology content" — exactly as specified (spec T).
6. Start Who First? — the setup screen shows the prioritization tagline
   and only prioritization-relevant questions appear in the session.
7. Note the session labels: "Question 1 of N", concise rationale after
   answering, "Explain more", "View source" — same honest machinery as
   daily study.
8. Answer a Medication Lab calculation — the M7 tolerance-aware engine
   grades it server-side; the rationale shows the worked math.
9. Start Rapid Response — the intro says speed never changes your mastery;
   there is no timer, no countdown, no speed bonus anywhere.
10. Start Boss Battle (needs 8+ questions) — the question screen shows
    "Round: Foundation", later "Round: Application", etc.
11. With a small bank, note the battle shrinks honestly — missing rounds
    simply do not appear; nothing is invented.
12. Finish any mode session — results show counts ("You answered X of N
    correctly"), never percentages-mastered or predicted scores.
13. Press "Back to study modes" — you land on the mode picker.
14. Open Today after studying — a muted line reads "Study streak: 1 day —
    today counts."
15. Study on a second consecutive day — "Study streak: 2 days…".
16. Open the app the NEXT morning before studying — the streak still shows
    with "A little studying today keeps it going." — never a broken-streak
    accusation.
17. Skip a full day — the streak quietly resets; nothing scolds you.
18. Check mastery after mode sessions (course → study) — the same mastery
    states move the same way as from practice; there is no separate game
    score anywhere.
19. Run a mode session with the worker/AI provider off — everything works;
    modes never call AI.
20. Free practice and the daily adaptive session behave exactly as in
    M7/M9 — untouched.
21. Sign in as a second user — none of the first user's sessions or streak
    data are visible (RLS; check 49 plus the M7–M9 checks).
22. Try to insert a session with a made-up session_type via the API — the
    check constraint rejects it.

## Known limitations (honest, not defects)

- Mode sessions are not resumable in v1 — the M9 plan/resume machinery
  stays adaptive-only (ADR-0026). Ending a mode session early still yields
  honest results.
- Boss Battle round sizes are proportional to what the bank holds; a very
  lopsided bank yields lopsided rounds (honest, but worth knowing).
- The streak reads the newest 400 attempt timestamps — streaks beyond ~400
  consecutive study events would undercount (irrelevant in practice; noted
  for completeness).
- No sound or haptics were added anywhere (spec AC allows subtle optional
  ones; v1 chooses none — reduced-motion preferences are therefore
  trivially respected, spec AB).

## Handoff to M11 (NOT implemented, spec AQ/AR)

Reusable for M11 patient simulation: the mode registry pattern (a
simulation step could be a registry entry with its own eligibility), the
fixed-seeded-plan session structure, the `session_type` labeling approach,
and the Find the Danger / Who First? interaction patterns as
single-decision building blocks. Deliberately absent, for M11+ to decide:
persistent patient state, evolving vitals, branching simulation, timed or
exam-simulation modes, faculty features, payments, deep analytics (M12),
and any analytics transport.
